5. Validation rules implemented

  • Transfer review, release, project, exact revision, material requirements and destination checks remain mandatory.
  • A production order can only be created from an Approved manufacturing handover, and only once per handover.
  • Handover approval requires Submitted status, an approved design review reference, released drawings, manufacturing instructions and every mandatory checklist item.
  • Operation completed plus rejected quantity cannot exceed planned quantity; overall completed cannot exceed order quantity.
  • An order closes only when every operation is Completed and the planned quantity is reached.
  • Quality inspection requires a Completed production order and accepted plus rejected must equal production quantity.
  • Quality approval requires every checklist item to be Pass or N/A.
  • Finished goods require approved quality; dispatch cannot exceed available accepted stock.
  • Invoice requires a dispatch and cannot be raised twice for the same dispatch.
  • Delivery requires a dispatch; Delivered requires received-by details.

6. Remaining limitations

  • NOT TESTED A single brand-new project driven through all 23 lifecycle stages in one uninterrupted run. The test used the existing PRJ-2026-042 conversion chain plus a complete operational branch from PRJ-2026-038. Forcing every stage for a new project would require additional legitimate drawings, reviews and releases rather than bypassing gates.
  • NOT TESTED Creating a new ECR from REV-2026-014. Eligibility and the action were verified, but no additional ECR was raised because REV-2026-013 already has ECR-2026-009 and the review release is correctly blocked by the Draft drawing.
  • All data remains frontend/localStorage only. There is no backend, authentication boundary, payment processing, transporter integration or legally binding approval.
  • Excel/PDF export, email and external service integrations are outside this implementation.
