Golden rule. Downstream records reference an exact revision. A newer revision must pass its own review and release before it can be transferred. Editing a released record or starting a new revision does not silently upgrade an existing transfer.

2. Phase 1 — Capture the customer requirement

Start in Customer & Sales → Customer Enquiry / Requirement. Create the enquiry with customer, contact, subject, product/machine, engineering domain, priority, quantity, units and required date. Complete the requirement specifications, then attach the customer’s technical documents or references.

Submit the enquiry for technical review. Use clarifications when the requirement is incomplete. The normal progression is:

Draft → Submitted → Under Technical Review → Ready for Quotation

If information is missing, the record moves to Clarification Required; record the customer response to return it to technical review. Only a Ready for Quotation enquiry should create a quotation.

Conversion control. A ready enquiry now shows Create Quotation when no quotation is linked. Once linked, the action becomes Open Quotation, preventing accidental duplicate quotations from the same requirement.

3. Phase 2 — Quotation and customer acceptance

Open Customer & Sales → Quotation & Technical Review. Create the quotation from the enquiry. The enquiry reference is preselected when the quotation is started from the enquiry action. Complete the technical scope, assumptions, exclusions, delivery basis and commercial summary.

Run the technical review in sequence:

Technical Review → Technically Accepted → Ready for Sales → Customer Submitted → Accepted

Record the customer reference when the quotation is submitted. Acceptance is the trigger for project conversion. Rejection or withdrawal ends the quotation path and leaves the enquiry available for revision.

4. Phase 3 — Convert accepted work into a project

From the accepted quotation, use the project conversion action. The system generates the next project ID, creates the project header, and writes the project reference back to the quotation. Confirm the customer, product, manager, priority, dates and enquiry/quotation references on the project record.

Then open Design Planning and create a design plan and the first engineering task. A practical plan includes concept work, detailed design, analysis, drawing preparation, BOM preparation and review preparation. Assign owners and target dates before work starts.

Project status. A converted project starts as New Request. Move it to Under Planning and then Design In Progress as work actually starts. Status and progress are manual project controls; they are not inferred from task completion.

5. Phase 4 — Concept development and selection

Create at least two concepts so the design has a documented alternative. For each concept record the design intent, working principle, advantages, limitations, estimated cost and risk. Use the comparison view to evaluate criteria and record the decision.

Select the preferred concept only after comparison. The selected concept becomes the design basis. Do not create detailed design records against an unselected or superseded concept unless the deviation is documented.

6. Phase 5 — Detailed mechanical design

Create the design item in Mechanical Engineering Design. Link the project and selected concept. Register the parts and assemblies that make up the design, including part number, description, material, revision, make/buy classification and parent assembly.

Record design calculations as evidence references. Calculations and analysis do not certify the design by themselves; they support the review decision.

7. Phase 6 — Engineering analysis and verification

Create the analysis record with load case, method, assumptions, acceptance criteria and evidence references. Submit it for review, assign the reviewer and set the due date. The reviewer records Verify, Request Changes or Reject; comments are mandatory for the latter two decisions.

Verification confirms that the evidence package and acceptance criteria were reviewed. It does not certify simulation accuracy and does not release the design.

8. Phase 7 — Manufacturing definition

Translate the design into manufacturing requirements. Record the process route, material specification, special characteristics, inspection points, gauges, acceptance criteria, tooling and work-instruction references. Submit the definition for review when complete.

Manufacturing definition is an engineering input to production, not a production order. It must remain aligned with the released drawing and BOM revision.

9. Phase 8 — BOM and drawing baselines

BOM baseline

  1. Create the BOM for the assembly/project.
  2. Add all make and buy lines with quantity, unit, material and references.
  3. Submit the BOM for review.
  4. Record the approval decision with comments.
  5. Release the approved BOM to create the controlled baseline.

E2E: BOM-2026-009 Rev A · In Progress → Under Review → Approved → Released · REL-REV-2026-003.

Drawing baseline

  1. Upload the CAD or drawing file; confirm preview.
  2. Register the drawing number, title, type, project, part and assembly.
  3. Submit the drawing for technical review.
  4. Approve or request changes from the CAD review queue.
  5. Release the approved drawing to make it transferable.

E2E: DRW-2026-011 Rev A · E2E-DWG-001 · Draft → Under Review → Approved → Released.

Release gate. A transfer can only use a BOM and drawing that are approved or released. A draft drawing or in-progress BOM blocks controlled release and downstream transfer. This is a real gate, not an error to bypass.

10. Phase 9 — Design review and approval

Create the review against the deliverable type, number and exact revision. Link the BOM, drawing and part where applicable. Select the required stages: Engineering, Manufacturing and, where contracted, Client.

Engineering review

  • Check the design and technical checklist. Every item must be Pass or N/A before approval.
  • Review requirements, assumptions, material references, calculations and analysis evidence.
  • Record comments with the relevant checklist item where useful.
  • Approve, reject or request changes. Approval advances to the next applicable stage.

Manufacturing review

  • Check manufacturability, tolerance/fit feasibility, process suitability and inspection requirements.
  • Complete every manufacturing checklist item before approval.
  • Record the decision. A rejection or change request must include comments.

Client approval

Where the contract requires client approval, submit the revision with the client reference and reviewer, record the client decision, and retain the client comments with the exact revision.

Checklist gate added during this review. The engineering and manufacturing approval buttons are now disabled while design, technical or manufacturing checklist items remain pending. The technical checklist is editable in the Engineering Review workspace. This prevents an approval from being recorded with an empty checklist.

11. Phase 10 — Change control

Raise an ECR when a released or in-review design must change. Record the reason, affected records, priority and owner. Complete the impact assessment across drawing, BOM, part, assembly, manufacturing definition, analysis and open production cases.

The ECO approval establishes the disposition. A revision update creates the new controlled revision. The new revision must then follow its own review and release path; existing transfers remain pinned to the earlier revision.

12. Phase 11 — Controlled release

Open Design Review & Approval → Release History. The eligibility panel only lists fully approved reviews whose linked BOM and drawing revisions are approved or released. Confirm the review, BOM revision and drawing revision, then create the controlled release.

The release record captures:

  • review ID, deliverable number and revision;
  • BOM ID and revision;
  • drawing ID and revision;
  • engineering and manufacturing approvers and approval date;
  • release ID, releasing authority and release date.

Controlled release now propagates the released state to the linked BOM and drawing. This is essential: without propagation, the transfer module would still see “Approved / Not released” and refuse the baseline.

Destination handover

  1. Open the transfer and choose Prepare Handover for Purchase or Production.
  2. Record the destination owner, prepared-by person, handover date and notes.
  3. Confirm the handover. The transfer moves to Awaiting Acknowledgement.
  4. The destination acknowledges, comments or rejects in its own workspace.
  5. Track the handover in Transfer Tracking and Transfer History.

For TRF-2026-010, a purchase handover was recorded against the Purchase — Sourcing cell and the transfer moved to Awaiting Acknowledgement with reference PUR-HO-2026-006.

14. Phase 13 — Readiness and production handover

Before production handover, confirm the manufacturing readiness record: released BOM, approved drawing set, manufacturing package index, material specifications, inspection requirements and handover cover sheet. Record open engineering issues with severity and owner. A readiness record with zero available documents remains incomplete even if the header is created.

Production handover requires a released manufacturing package. The E2E drawing is released and purchase-transferable, but no released manufacturing package was created for E2E, so the production destination remains correctly blocked. Do not work around this by selecting an unrelated seeded package.

15. Phase 14 — Production support and as-built

When production raises a query, create a support case from Manufacturing Support & As-Built. Link the project and the affected drawing, BOM, part or assembly. Assign an owner and priority. Record the engineering response and close the case only when the disposition is accepted.

18. Operational checklist

Before releasing

  • Project, revision and customer references are correct.
  • BOM is approved and released for the exact revision.
  • Drawing is approved and released for the exact revision.
  • Engineering and manufacturing checklists are complete.
  • Client approval is recorded where required.
  • Open ECR/ECO impact is dispositioned.
  • Release History shows the review as eligible.

Before transferring

  • Source release ID is visible and current.
  • Destination is eligible for the deliverable type.
  • BOM revision matches the released revision.
  • Material quantities are available for purchase.
  • Manufacturing package is available for production.
  • Attachments and technical notes are complete.
  • Validation has zero mandatory invalid results.
