1. Audit approach

Each primary register was opened at desktop width. The first row’s three-dot trigger was activated and the resulting menu labels were captured. The menu was then closed and the next register tested. Inline actions outside the three-dot menu were reviewed separately, because several modules deliberately place workflow decisions in the record panel rather than in a row menu.

Menu position was also checked against the viewport. When the action button itself is visible inside a horizontally scrolled table, the right-aligned menu opens inside the viewport. When the action column is offscreen, the table must be scrolled first; this is normal wide-table behaviour and is not a clipped menu once the trigger is visible.

7. Recommendations

The following are worthwhile follow-ups but were not added during this testing cycle because they are enhancements rather than missing workflow actions:

  • Add a sticky first column and/or sticky action column to the widest registers so identity and actions remain visible during horizontal scroll.
  • Expose a single “Create review from drawing/BOM” action that pre-fills deliverable, revision, linked BOM and reviewers, replacing the current separate submit and review steps.
  • Add a live released manufacturing package source for production transfer, rather than relying on seeded package fixtures.
  • Expose bulk actions (bulk archive, bulk submit, bulk release) for high-volume registers.
  • Add a visible “review checklist incomplete” state on the review register row, not only inside the stage page.

8. Conclusion

Row-level action menus are consistently implemented through a shared component, with appropriate state-aware items and no clipping defect once the table trigger is visible. The meaningful gaps were not missing three-dot items but missing cross-module commands and data wiring. Those gaps are now addressed for enquiry conversion, approval checklists, controlled-release propagation and live transfer sourcing.
