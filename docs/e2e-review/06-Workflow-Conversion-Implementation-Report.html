1. What was implemented

  • One shared conversion service in src/context/WorkflowConversionContext.jsx, mounted inside every module provider. Both row-menu and detail-page conversions call the same runConversion logic.
  • Persistent link registry in md-workflow-conversions-v1. Each conversion stores source type/ID, destination type/ID, label, actor and timestamp.
  • Confirmation dialog with eligible/blocked destinations, reasons, duplicate blocking and a link to the destination record.
  • Shared WorkflowLinks panel on key detail pages, showing incoming source and outgoing destination references with conversion history.
  • Register three-dot actions added to Enquiry, Quotation, Project, Plan, Task, Concept, Mechanical Design, Analysis, Manufacturing Definition, BOM, Drawing, Review and Transfer registers.
  • Detail-page Convert actions added to Enquiry, Quotation, Project, Mechanical Design, Analysis, Manufacturing Definition, BOM, Review, Plan and Task views.

5. Defects found and fixed

  1. Analysis → Manufacturing crash. The converted analysis record had no name, causing toUpperCase on undefined. Fixed by using the analysis title and its linked part; conversion then created MFD-2026-017 successfully.
  2. Incomplete transfer destination. A BOM conversion created a transfer without the review reference or material requirements, so validation returned Invalid. Fixed by copying the linked review ID and mapping BOM items into material requirements. The corrected creation path was not re-run before this report.
  3. Enquiry duplicate risk. An enquiry that already had a quotation but no conversion registry entry could be converted again. Eligibility now also checks existing quotations and quotationRef.
  4. Detail-page parity gap. Plan and Task detail modals only offered Edit. Shared Convert actions and Workflow Links were added.

7. Remaining limitations

  • Manufacturing Tracking and Delivery & Service Tracking remain read-only by their existing module contract, so the final two business handovers cannot create records without redesigning those modules.
  • The new review REV-2026-014 was created correctly but not approved; its checklist gates still require reviewer decisions. The ECR test therefore used the previously released REV-2026-013.
  • TRF-2026-013 remains an invalid draft produced before the transfer-copy fix. It was not deleted, in line with the rule to preserve test records.
  • Dark, tablet and mobile three-dot menus were inherited from the shared Dropdown rather than exhaustively re-tested on every register.
